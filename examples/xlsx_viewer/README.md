# 本地 Excel 查看 Demo

独立的 PySide6 + openpyxl 示例，不依赖或修改 XlsxWriter 核心。只提供
“打开—查看”，不编辑、不保存，也不执行宏、公式或外部链接。

## 安装与启动

使用 Python 3.10 或更新版本，在仓库根目录执行：

```sh
python3 -m venv .venv-viewer
source .venv-viewer/bin/activate
python -m pip install -r examples/xlsx_viewer/requirements.txt
python examples/xlsx_viewer/viewer.py
```

Windows 将前两行替换为 `py -m venv .venv-viewer` 和
`.venv-viewer\Scripts\activate`。启动需有桌面环境及 Qt 所需的系统图形库；
Linux 桌面可能还需安装发行版提供的 Qt/xcb 运行库。

点击“打开工作簿…”通过系统文件选择器选择 `.xlsx` 或 `.xlsm`，使用工作表
下拉框切换。显示 A、B、…列标题和从 1 开始的行标题；长文本可悬停查看。
隐藏工作表也列出。有效的空白工作表显示“空工作表”，0 字节文件则报错。

普通公式直接显示 `=SUM(...)` 等原始公式文本（`data_only=False`），不读取缓存
计算结果。数组公式显示其锚点的公式文本；无普通公式文本的数据表公式显示占位提示。
布尔值、数字、日期等采用 openpyxl 值的字符串形式；这不是 Excel 的格式化渲染器，
不复现数字格式、样式、合并单元格布局、图表或图片，图表工作表不列出。
`.xlsm` 中的 VBA 不加载、不执行。工作表编辑保护不影响查看；需要打开密码的
加密工作簿不支持，请在 Excel 中另存为未加密的文件。

## 加载限制

整个工作簿在独立 Python 子进程中只读解析。窗口可以继续响应；可取消加载，
30 秒未完成会终止子进程，关闭窗口也会停止加载。成功后使用表格模型按需绘制，
不为每个单元格创建控件、不逐列扫描自动计算宽度。

本 Demo 采用以下保守上限；任一工作表或工作簿超限会拒绝整个文件，提示原因，
不会静默截断显示：

| 项目 | 上限 |
| --- | --- |
| 文件大小 | 20 MiB |
| ZIP 声明的总解压体积 / 条目数量 | 100 MiB / 2000 |
| 单元格工作表数量 | 100 |
| 每张工作表行 / 列 | 10000 / 256（IV） |
| 单元格显示文本累计字符 | 1000000 |

远端单元格的格式或膨胀的区域元数据也可能触发限制。检查声明区域后会重新扫描
实际数据，防止区域元数据过小导致遗漏。损坏的 ZIP/XML、非 Excel 文件、缺失文件、
密码加密或旧版 OLE 文件均有错误提示。上述限制用于本地 Demo 的响应性，
子进程没有操作系统级内存配额，不构成处理恶意文件的安全沙箱。

## 自动化验证（无需实际桌面显示）

安装上述依赖后，在仓库根目录执行：

```sh
python -m compileall -q examples/xlsx_viewer
python -m unittest discover -s examples/xlsx_viewer -p 'test_*.py' -v
```

测试使用标准库 unittest、临时生成的工作簿和 Qt 的 `offscreen` 平台，覆盖
值/公式、空表、隐藏表、编辑保护、只读模型及文件不变、标题、工作表切换、异常文件、
大小限制、虚假的区域元数据、子进程协议、取消/超时及失败后的重新打开。
原生选择器在测试中被替换，`.xlsm` 使用无宏 OOXML 测试文件；真实桌面上的原生
对话框、各平台外观、真实 VBA/加密文件仍需手动验证。
